## DD-001 ルーレットは「縦式パネル・リール」＋「レベルアップでパネルがランダム成長」（オレカバトル式）

**決定日**：2026-06-28 ／ **状態**：確定

### 決まったこと
1. **方式は縦式パネル・リール**。円形に回す方式ではなく、縦一列に並んだ行動パネル（コマ）が
   上下にスクロールし、中央の停止ラインに来たパネルの行動を実行する（スロットマシンの1リール）。
   参考イメージはアーケード型カードバトルの縦パネル・ルーレット。
2. 各パネルには **★ランク（★〜★★★★）** があり、★が多いほど強力。**「ミス」枠**も混ざりうる
   （止まると行動失敗。低ランクほど多い＝育てる動機）。
3. **「型（フレーム）」はプレイヤーが構成**できる（パネル数・型テンプレ・ロック構成）。
   ただし **具体的な技はレベルアップでランダムに変化**する：
   - レベルアップごとに、ロックしていないパネルから1枚が抽選で別の技／上位の技に化ける。
   - 変化先は同系統（family）プール＋同属性が出やすい。まれに飛び級・必殺パネル出現（当たり個体）。
4. **事故救済**：パネルロック（変化対象から除外）＋リロール素材（直近の変化を振り直し）。
5. 手動ストップ（任意ON）で狙いパネルを引きにいける＝**運を腕で操作**。おまかせ（自動停止）が既定。

### なぜ
- アーケードのテンポ感（縦リールの停止快感）と、育成のランダム性（個体差・厳選・愛着）を両立。
- 「同じ種でもリール構成が個体ごとに違う」＝唯一の自分の子、という所有感（独自要素①の核）。
- ロック＋リロールで、ランダムでも理不尽にならない主導権をプレイヤーに残す。

### 反映先
- `docs/game-design.md` 5-3 / 5-4 / 4-12 / 5-14 / 10-3〜10-5 / 11-2 / 15章ワイヤー
- `data/monsters.json` v2：`rouletteSpec`（縦式リール）、`growthSpec`（ランダム成長）、
  `familyGrowthPools`（系統別の変化プール）、各モンスターの `reel`（★ランク＋ミス枠付き）

### 旧仕様からの変更点
- 旧：プレイヤーが盤面の技と「重み」を完全決定（決定論）／円形回転。
- 新：プレイヤーは「型」を決め、中身はランダム成長／縦式リール。`weight` 概念は廃止。

## DD-002 覚醒（可愛い→かっこいいの見た目変化）は採用確定

**決定日**：2026-06-28 ／ **状態**：確定（最優先で実装したい独自要素）

- 育成（覚醒）で**頭身・シルエット・表情が幼体→凛々しい姿へ変化**する見た目演出を必ず入れる。
- 成長の報酬を数値ではなく"見た目"で渡し、愛着の対象が育つ実感を作る。
- 反映先：`docs/game-design.md` 10-6（覚醒）、11-1（アート原則）、独自要素①〜③の愛着軸。

## DD-003 配合は「博打」ではなく「設計」（前提の確認）

**決定日**：2026-06-28 ／ **状態**：確定（既存設計の再確認）

- 配合は当初から博打ではない。**プレビューで系統・ランク帯・候補・継承予定を提示**し、後悔を生まない。
- 「だいたい分かるが最後だけ少し驚く」黄金比は維持（完全固定にはしない）。
- 反映先：`docs/game-design.md` 7-13 / 4-9 / 4-10。

## DD-004 強敵ボスは「撃破後の共鳴クエストで限定スカウト」＋「配合難易度の引き上げ」で希少性を担保

**決定日**：2026-06-28 ／ **状態**：確定（方針）

- ボスは戦闘中はスカウト不可。代わりに**撃破後の共鳴クエスト**で条件付き限定スカウトを用意（長期目標）。
  - 反映先：`data/chapters.json` の 5/7/9 章ボス `postClearScout: true`、`docs/chapters.md`、`docs/game-design.md` 5-11 / 6-6。
- それでも入手過多になる場合は、**該当系統の配合難易度（必要世代・条件）を引き上げる**ことで希少性を調整するノブを用意。
  - 反映先：`data/fusion_rules.json` の特殊配合 `conditions`（章クリア後・親条件・素材要求）を強める運用。
- 運用方針：まず「共鳴クエスト」で入手導線を作り、バランス次第で「配合難易度」を上げて希少性を守る、の二段構え。
