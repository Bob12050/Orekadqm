## 1. ゲーム全体の方向性

### 1-1. 仮タイトル案（5案）

| 案 | 読み | 狙い |
| --- | --- | --- |
| **コドモナ・サーガ** | KODOMONA SAGA | 「子ども＋モンスター（コドモナ）」造語。低年齢にも親しみやすく、サーガで物語性 |
| **ルーレットビースト** | RouletteBeast | コア機構（ルーレット）を前面に。検索性・記憶性が高い |
| **きみとモンスターの星** | Hoshi to Kemono | 情緒・絆を押し出す日本語タイトル。やさしい雰囲気 |
| **アルカナ・タクティカ** | ARCANA TACTICA | 戦略性・かっこよさ寄り。コアゲーマー訴求 |
| **ぐるぐるバトル ピクシーズ** | GuruGuru Pixies | 低年齢・カジュアル全振り。オノマトペで操作感を表現 |

**本書での仮称**：以降は **「コドモナ・サーガ」** を仮タイトルとして記述する。

### 1-2. 一言コンセプト

> **「タップとルーレットだけで、本格モンスター配合RPGが手のひらに」**

片手・短時間・直感操作で始められるのに、配合と編成を突き詰めると驚くほど奥が深い。
「入口はやさしく、底は深く」を一行で体現する。

### 1-3. ターゲットユーザー

- **コア層（中心）**：小学校高学年〜中学生、およびその親世代（30〜40代のかつてのモンスターRPG経験者）。
- **サブ層①**：通勤・休憩のスキマ時間に1〜3戦したいライトRPGファン（社会人）。
- **サブ層②**：図鑑コンプ・最強配合を追うやり込み勢（コレクター気質）。
- **共通する欲求**：「自分だけのモンスターを育て、組み合わせ、見せたい」。

> ターゲットを「小学生だけ」に絞らないのが重要。**親子同時プレイ**・**世代をまたぐ会話**を起こせる設計にする。

### 1-4. 差別化できる魅力（なぜ既存と違うのか）

1. **ルーレット式コマンド × タップ・ターゲティングの融合**
   - 行動は半自動（ルーレット）でテンポよく、しかし「誰を狙うか」はプレイヤーが指で決める。
   - 「運でテンポを出し、判断で勝ちを掴む」＝アーケードの爽快感と RPG の戦略の両立。
2. **配合が"博打"ではなく"設計"になる予測UI**
   - 配合前に「結果プレビュー（系統・ランク帯・引き継ぎ候補）」を提示。後悔しにくい。
   - 完全固定だけにしないので無限に発見があるが、逆引き検索で迷子にならない。
3. **スカウトのストレス最小化設計**
   - 「低確率を引くまで粘る」のではなく、**弱らせる・状態異常・スカウト枠の編成**で能動的に成功率を上げる。
   - 失敗してもメリット（スカウトゲージ蓄積＝次回成功率UP）が残り、無駄撃ちにならない。
4. **1戦2〜5分・1章＝1セッションのテンポ設計**
   - スマホの可処分時間（数分単位）に最適化。中断・再開がストレスにならない。
5. **「可愛い→かっこいい」の成長変化を可視化**
   - 配合・覚醒でモンスターの見た目が"あどけない"から"凛々しい"へ変化。育てる動機を見た目で報酬化。

### 1-5. アート方針 — 可愛い × かっこいい の両立

- **基本形（低ランク・初期）**：頭身2〜2.5、丸み・大きな目・短い手足＝**可愛い**を担保。
- **成長/上位形（高ランク・覚醒後）**：頭身3〜4、シルエットにエッジ・装甲・流線＝**かっこいい**へ。
- **共通ルール**：
  - 線は太め・色面はフラット＋簡易グラデ（低スペック描画でも破綻しない）。
  - 「目」を最重要パーツに。可愛さもかっこよさも目の形・ハイライトで表現を切り替える。
  - 配色は系統ごとにキーカラーを固定（後述 11章）。同系統は一目で分かる。
- **バトル中だけ"かっこいい演出"**：ホームでは可愛く揺れ、戦闘では構え・エフェクトで凛々しく。**TPOで表情を切替**。

### 1-6. 世界観の方向性

- **舞台**：星のかけら「アルカ」が大地に降り、そこから生命（モンスター＝**コドモナ**）が生まれた世界「**オルセア**」。
- **トーン**：明るく牧歌的な表側と、星のかけらの暴走（"にごり"）という影。低年齢にも怖すぎず、しかし芯のある物語。
- **プレイヤーの立場**：コドモナと心を通わせる「**ハーモナイザー（共鳴者）**」。倒すのではなく"鎮め、仲間にする"存在。
   - → スカウトの世界観的正当化。「敵を倒す」より「共鳴して仲間にする」をコアに据える。
- **章ごとに異なる土地（草原・水郷・砂漠・空島・機械都市・星の中心…）** を旅し、各地の"にごり"を鎮めていく。

### 1-7. 毎日遊びたくなるコア体験

- **短期（1セッション＝3〜10分）**：1〜2戦してスカウト成功 → 図鑑が1体埋まる小さな達成。
- **中期（数日）**：素材モンスターを集め、狙った配合を完成させる → パーティが目に見えて強くなる。
- **長期（数週間〜）**：図鑑コンプ、特殊配合の発見、高難度章のボス攻略、最強編成の研究。
- **デイリー設計**：
  - 「今日のにごり地点（デイリーステージ）」＝1日1回のレア素材・経験値ボーナス。
  - 「共鳴の祠（放置/タイマー報酬）」＝ログインで素材が貯まる軽い動機。
  - **過剰なスタミナ課金圧をかけない**（低年齢向けの倫理＋PWAの気軽さを優先）。

## 2. コア体験

プレイヤーが繰り返し味わう「気持ちよさの核」を3つに定義する。

1. **「ぐるっ、ピタッ、ドンッ」のリズム**
   ルーレットが回る（ぐるっ）→ 枠が止まる（ピタッ）→ タップした敵に技が炸裂（ドンッ）。
   この0.8〜1.5秒のリズムを全戦闘の基本ビートにする。テンポが命。

2. **「弱らせて、共鳴して、仲間になる」瞬間**
   敵を削り、状態異常で隙を作り、スカウトアタックを当て、光に包まれて仲間化。
   "倒した"より"分かり合えた"という情緒的報酬を演出で最大化する。

3. **「掛け合わせたら、想像を超えるのが生まれた」驚き**
   配合プレビューで"だいたい"を見せつつ、引き継ぎ抽選やレア分岐で"想像以上"が起きる。
   設計（予測可能）と発見（予測不能）のバランス。

> この3つを満たさない機能追加は「コア体験を薄める」と判断し、優先度を下げる。

## 3. 基本ゲームループ

```
[ホーム]
  └→ 章・エリア選択
        └→ ステージ選択
              └→ エンカウント（最大4対最大4）
                    └→ ルーレット式バトル
                          ├→ ターゲット指定 / 通常戦闘
                          └→ スカウトアタック
                                └→ 勝利・スカウト判定
                                      └→ 報酬獲得（経験値・素材・コドモナ）
                                            └→ 育成（レベル/スキル/ルーレット枠）
                                                  └→ 配合（新コドモナ生成）
                                                        └→ 強い編成で次ステージへ ↺
```

### 3-1. 短期モチベーション（1セッション内）

- 目標：「このステージをクリアする」「あの敵をスカウトする」。
- 報酬：戦闘勝利の爽快演出、図鑑の即時更新、レベルアップのファンファーレ。
- 設計意図：3〜10分で必ず「何か得た」状態にする。手ぶらで終わらせない。

### 3-2. 中期モチベーション（数日）

- 目標：「狙った配合を完成させる」「パーティを次章基準まで底上げする」。
- 報酬：配合で見た目・性能が変わる、推奨強さを超えてボスを攻略できる。
- 設計意図：素材集め → 配合 → 戦力UP の「育成サイクル」を回す動機を常に提示。

### 3-3. 長期モチベーション（数週間〜）

- 目標：「図鑑コンプ」「特殊配合の発見」「最高ランク・覚醒個体の作成」「高難度章クリア」。
- 報酬：称号、図鑑コンプ率、レア演出、自慢できる編成。
- 設計意図：終わりのない"研究"の余地。やり込み勢を逃さない。

### 3-4. ループを気持ちよくする要点

- **遷移は最短2タップ**：ホーム → ステージ → 戦闘開始まで指の移動を最小化。
- **戦闘後は"次の一手"を即提示**：勝利画面に「もう一度」「配合へ」「育成へ」を並べる。
- **中断耐性**：戦闘以外はいつでも閉じてOK。戦闘も「途中セーブ（オートバトル委任）」を許容。

## 4. 画面一覧とUI設計

スマホ縦画面（基準解像度 **390 × 844 / セーフエリア考慮**）前提。
各画面に「目的 / 表示情報 / 主要ボタン / タップ操作 / 遷移 / 片手操作の工夫 / 子ども配慮 / 本格演出 / PWA実装メモ」を記す。

> **共通レイアウト規約**
> - 画面下部 25%（親指の自然到達域）を**主要アクション帯**にする。
> - 戻る/ホームは**左下固定**。確定/次へは**右下固定**。誤タップ防止に確定系は少し大きく。
> - 上部はタイトル/所持リソース表示のみ（情報表示専用、操作はなるべく置かない）。
> - モーダルは下からせり上がる**ボトムシート**を基本。閉じるは下スワイプでも可。

### 4-1. タイトル画面
- **目的**：起動演出、続きから/はじめから、設定への入口。
- **表示情報**：ロゴ、メインビジュアル（看板コドモナ）、バージョン、セーブの有無。
- **主要ボタン**：`はじめる`（中央大）、`つづきから`、`設定`、`図鑑（ゲスト閲覧可）`。
- **タップ操作**：ロゴタップで看板コドモナが鳴く（小演出）。
- **遷移**：→ ホーム / 設定 / （初回）チュートリアル。
- **片手配慮**：主要ボタンは下半分に集約。
- **子ども配慮**：文字が読めなくてもアイコンで分かる（▶＝はじめる）。
- **本格演出**：背景パララックス、星のかけらが降る微アニメ。
- **PWA**：初回はここで `localStorage` セーブ有無を判定。Service Worker 登録もここ。

### 4-2. ホーム画面
- **目的**：全機能へのハブ。今日やることを提示。
- **表示情報**：看板コドモナ（タップで反応）、所持コイン/素材、スタミナ（緩め）、お知らせ、デイリー進捗。
- **主要ボタン**：`ぼうけん（章選択）`（最大・中央下）、`そだてる（育成）`、`はいごう（配合）`、`ずかん`、`へんせい`、`設定`。
- **タップ操作**：看板コドモナをなでると好感度小UP（情緒フック）。
- **遷移**：各機能画面へ1タップ。
- **片手配慮**：6機能を下部2×3グリッドに。中央列を最頻機能に。
- **子ども配慮**：各ボタンに大アイコン＋ふりがな。
- **本格演出**：時間帯で背景の空が変化（朝昼夕夜）。
- **PWA**：ホームをルート画面に。各機能は遅延ロード（コード分割）。

### 4-3. 章選択画面
- **目的**：10章のうち解放済みを選ぶ。世界観の旅情を演出。
- **表示情報**：世界地図（縦スクロール or すごろく状の道）、各章のクリア状況（★0〜3）、推奨強さ。
- **主要ボタン**：章ノードをタップ、`もどる`。
- **タップ操作**：章ノードタップ → エリア概要ポップ → `すすむ`。
- **遷移**：→ ステージ選択。
- **片手配慮**：縦スクロールの道。現在地に自動スクロール。
- **子ども配慮**：未解放章は鍵アイコン＋もやで明示。
- **本格演出**：解放時に道が光ってつながるアニメ。
- **PWA**：地図は1枚SVG＋ノード座標データで軽量化。

### 4-4. ステージ選択画面
- **目的**：章内の複数ステージから選ぶ。
- **表示情報**：ステージ名、出現系統アイコン、推奨強さ、クリア★、ドロップ素材プレビュー、初回報酬。
- **主要ボタン**：ステージカード、`へんせいを確認`、`いざ、ぼうけん`（右下）。
- **タップ操作**：カードタップで詳細シート → 編成確認 → 開始。
- **遷移**：→ パーティ確認（任意）→ バトル。
- **片手配慮**：ステージは横スワイプのカルーセル。開始ボタンは右下固定。
- **子ども配慮**：難易度を星と色（緑→黄→赤）で直感表示。
- **本格演出**：ステージごとのサムネイル背景。
- **PWA**：データは `chapters.json` 駆動。サムネは遅延ロード。

### 4-5. パーティ編成画面
- **目的**：最大4体の出撃メンバーと並び（前衛/後衛 or 行動枠）を決める。
- **表示情報**：編成枠4、控えリスト、合計戦力値、系統・属性バランス、リーダー設定。
- **主要ボタン**：`オート編成`、`保存`、`もどる`。
- **タップ操作**：控えからドラッグ&ドロップ、または枠タップ→一覧から選択。
- **遷移**：← ホーム/ステージ選択。
- **片手配慮**：枠は上、控えリストは下（親指で控えを選び上の枠へ）。タップ選択方式をドラッグの代替に常設。
- **子ども配慮**：「つよさメーター」で編成の良し悪しを色バーで提示。`オート編成`で迷子防止。
- **本格演出**：編成完了時にパーティが整列する小演出。
- **PWA**：状態は1つのストア（party配列）。並びはindexで管理。

### 4-6. モンスター一覧画面
- **目的**：所持コドモナを一覧・管理。
- **表示情報**：サムネ、名前、Lv、系統/属性アイコン、ランク、ロック、お気に入り、強さ。
- **主要ボタン**：`並べ替え`、`絞り込み`、`複数選択`、各カード。
- **タップ操作**：カードタップ→詳細。長押し→複数選択（配合素材選びに直結）。
- **遷移**：→ モンスター詳細 / 配合 / 育成。
- **片手配慮**：縦グリッド3列。フィルタは上部ピル、適用は即時。
- **子ども配慮**：系統色のカード枠で識別。ロック中は鍵。
- **本格演出**：レア個体はカード枠がきらめく。
- **PWA**：仮想スクロール（多数所持でも軽い）。

### 4-7. モンスター詳細画面
- **目的**：1体の全情報と各種アクションの起点。
- **表示情報**：大きな立ち絵、名前/系統/ランク/属性、ステータス、習得スキル、ルーレット枠構成、配合経歴、好感度、図鑑番号。
- **主要ボタン**：`そだてる`、`はいごうへ`、`へんせいに入れる`、`ロック`、`もどる`。
- **タップ操作**：立ち絵タップで鳴き＆モーション。ステータスは折りたたみ展開。
- **遷移**：→ 育成 / 配合 / 編成。
- **片手配慮**：アクション帯は下固定。情報はスクロール。
- **子ども配慮**：難語にツールチップ（「？」タップで子ども向け説明）。
- **本格演出**：立ち絵の呼吸アニメ、属性オーラ。
- **PWA**：立ち絵はWebP/PNG＋CSSアニメ。Lottieは任意。

### 4-8. 育成画面
- **目的**：レベル/スキル/技強化/ルーレット枠を成長させる。
- **表示情報**：現Lv・経験値バー、ステータス、習得可能スキルツリー、ルーレット枠スロット、必要素材。
- **主要ボタン**：`Lvアップ（素材使用）`、`スキル習得`、`ルーレット枠を編集`、`もどる`。
- **タップ操作**：枠タップ→入れ替え、スキルノードタップ→習得確認。
- **遷移**：← 詳細。
- **片手配慮**：タブ（成長/スキル/ルーレット）を下部に。
- **子ども配慮**：「いまのおすすめ」を1タップで実行できる導線。
- **本格演出**：Lvアップ時のステータス増加カウントアップ＆光。
- **PWA**：成長計算は純関数で（テスト容易）。

### 4-9. 配合画面
- **目的**：親2体を選び、生まれる子をプレビューして配合実行。
- **表示情報**：親A/親Bスロット、結果プレビュー（系統・ランク帯・候補名・引き継ぎ候補・属性）、必要コスト、警告（親消費）。
- **主要ボタン**：`親を選ぶ`、`引き継ぎを選択`、`おすすめ配合`、`逆引き検索`、`はいごうする`（要確認）。
- **タップ操作**：スロットタップ→一覧から選択。引き継ぎスキルをチェックボックスで選ぶ。
- **遷移**：→ 配合結果。
- **片手配慮**：親スロットは中央上、確定は右下。
- **子ども配慮**：「このふたりからは○○系がうまれそう！」と一言で要約。
- **本格演出**：親同士が光で混ざり合うプレビューアニメ。
- **PWA**：プレビューは `fusion_rules.json` を引く純関数 `previewFusion(a,b)`。

### 4-10. 配合結果画面
- **目的**：生まれた子の披露と達成感の最大化。
- **表示情報**：新コドモナの立ち絵、名前、系統/ランク/属性、継承スキル、初期ステータス、図鑑新規/特殊配合バッジ。
- **主要ボタン**：`なづける（任意改名）`、`もういちど`、`へんせいに入れる`、`OK`。
- **タップ操作**：タップで殻が割れて登場（演出スキップ可・長押しで早送り）。
- **遷移**：← 配合 / → 詳細。
- **片手配慮**：OKは右下大。
- **子ども配慮**：特殊配合は「★とくべつなコドモナ！」と派手に祝う。
- **本格演出**：レアランクは画面全体エフェクト＋専用SE。
- **PWA**：演出はCSS/Canvasで段階表示。重い端末は簡易版にフォールバック。

### 4-11. バトル画面（メイン）
- **目的**：4対4のルーレット戦闘の主戦場。
- **表示情報**：上＝敵最大4体（HPバー/状態異常アイコン/ターゲットマーカー）、下＝味方最大4体、中央＝ログ/演出、下帯＝ルーレット＆コマンド、各種ゲージ（スカウト/必殺）。

### 4-12. ルーレット操作画面（バトル下帯のUI詳細｜縦式リール）
- **目的**：各味方の行動を縦式パネル・リールで決定／介入する。
- **表示方式**：**縦スクロールのリール**（円形回転ではない）。中央に**停止ライン**を置き、その上下に前後のパネルがちら見えする（スロットマシンの1リール）。各パネルは行動アイコン＋★ランク＋系統色。
- **表示情報**：行動中コドモナのリール（4〜8枚）、停止ライン、★ランク表示、ミス枠の有無。
- **主要ボタン**：`ストップ`（手動停止モード時）、`おまかせ`（自動停止）。
- **タップ操作**：
  - **おまかせモード（既定）**：リールが自動で減速・停止。テンポ重視・低年齢向け。
  - **ストップモード（任意ON）**：縦スクロール中にタップで止め、狙ったパネルを引きにいく（上級者の介入余地＝運を腕に変える）。
- **遷移**：停止パネル確定 → ターゲットへ行動実行。
- **片手配慮**：リールは下中央、`ストップ`はリール直下の大ボタン。親指の自然到達域。
- **子ども配慮**：停止ラインに来たパネルが**ポンッと拡大**＋発光。何が出たか一目で分かる。
- **本格演出**：スクロールは加速→減速のイージング、停止直前に"あと一枚"のタメ、停止時に「カチッ」とハプティック（対応端末）。
- **PWA**：縦スクロールは `transform: translateY` ＋ `requestAnimationFrame`。**停止パネルは事前抽選**で確定し、演出だけ後追いで見せる（同期ズレ・チート防止）。リールは固定高のリスト1本で実装が軽い。

### 4-13. ターゲット選択UI

### 4-14. スカウトアタックUI

## 5. バトルシステム

最大4体 対 最大4体。**ルーレットで行動が決まり、ターゲットは指で決める**コマンドバトル。
1戦 2〜5分。運（ルーレット/会心）と腕（ターゲット判断/編成/育成）の比率を **おおむね 4:6**（腕が勝つ）に調整する。

### 5-1. ターンの流れ（1ラウンド）

1. **行動順決定**：全生存ユニットを「素早さ＋小乱数」で降順ソート → 行動キューを作る。
2. **各ユニットの手番**：
   - 味方：ルーレットが回り、行動枠が決定（おまかせ自動 or 手動ストップ）。ターゲットは現在ロック（無ければAI）。
   - 敵：AIが行動とターゲットを選択。
3. **行動解決**：命中/回避/会心/属性相性/状態異常を計算 → ダメージ/効果適用 → 演出。
4. **手番終了**：状態異常のターン経過処理（毒ダメージ等）。
5. 全ユニットが行動 → **ラウンド終了**。勝敗判定（敵全滅/味方全滅）→ 続行 or 終了。

> テンポ確保：演出は「結果先決め・見せは後追い」。×2速度時は演出を短縮（後述5-12）。

### 5-2. 素早さ・行動順

- 各ユニットに `speed` ステータス。行動順は `speed * (0.9〜1.1乱数)` 降順。
- **同速時**は味方優先（プレイヤー有利＝ストレス低減）。
- 状態異常「鈍足」「加速」で順序が動く（戦略要素）。
- ラウンドごとに再計算（加速バフが効いてくる手応え）。

### 5-3. ルーレットの仕様

> **方式：縦式パネル・リール（円形回転ではない）。** 参考イメージはアーケード型カードバトルの
> 縦パネル・ルーレット。各コドモナは縦一列に並んだ**行動パネル（コマ）**を持ち、戦闘ではこの列が
> 上下にスクロールし、中央の停止ラインに来たパネルの行動を実行する。スロットマシンの1リールに近い。

- 各コドモナは縦一列の **4〜8枚の行動パネル**を持つ（パネル数は育成/ランクで拡張）。
- 各パネルには **★ランク（★〜★★★★）** がある。★が多いほど強力（右肩上がりの並びが基本）。
- パネルには **「ミス」枠**も混ざりうる（止まると行動失敗）。これが「弱い枠を育てて強くする」動機になる（10-5）。
- 1手番ごとにリールが縦スクロール → 停止ラインのパネルの行動を実行。
- **おまかせモード（既定）**：自動で減速・停止（停止位置は均等寄りの抽選）。テンポ重視・低年齢向け。
- **ストップモード（任意ON）**：スクロール中にタップで止め、狙ったパネルを引きにいく＝**運を腕で操作**。外せばミス枠や弱パネルに止まるリスクも。
- **パネルの中身（型）はプレイヤーが構成**できるが、**具体的な技はレベルアップでランダムに変化**していく（オレカ式・後述10-3/10-5）。決定論ではなく"育成の引き"が個体差を生む。
- 結果と演出を分離：内部で停止パネルを確定 → 演出としてスクロールを見せる（同期ズレ・チート防止）。

### 5-4. ルーレットのパネル列の例（縦リール・サンプル）

獣系アタッカー「モコル（Lv低）」の縦リール例（上から下へ並ぶ。停止ラインに来た枠を実行）：

| 位置 | パネル | ★ランク | 分類 | 効果 |
| --- | --- | --- | --- | --- |
| 1 | ミス | ★ | ミス | 行動失敗（育成で別の技に化ける種枠） |
| 2 | ひっかき | ★★ | 攻撃(単体) | 基礎物理ダメージ |
| 3 | からだ当たり | ★★ | 攻撃(単体) | 物理＋低確率ひるみ |
| 4 | うなり | ★ | 補助 | 対象の攻撃ダウン |
| 5 | みだれ爪 | ★★★ | 攻撃(ランダム複数) | 敵ランダムに2〜3回 |
| 6 | きずなの牙 | ★★★★ | 必殺(単体大) | 高倍率＋会心率UP |

> - 序盤は「ミス」「★」枠が混じり不安定 → **レベルアップで1枠ずつ強い技に化け、リールが育つ**実感がある。
> - 「攻撃中心だが補助も混ざる」「強★枠ほど稀に止まる位置」にすることで、**毎手番に小さな一喜一憂**が生まれる。
> - ストップモードなら、強★枠（きずなの牙）を狙って止めにいける＝**運を腕で掴む**。

### 5-5. 行動の分類

| 分類 | 例 | 対象 | 役割 |
| --- | --- | --- | --- |
| 攻撃 | 物理/属性攻撃 | 単体/全体/ランダム | ダメージ |
| 魔法 | 属性魔法 | 単体/全体 | 属性ダメージ・遠隔 |
| 補助 | バフ/デバフ | 自己/味方/敵 | 攻防速・命中・属性耐性の増減 |
| 回復 | HP回復/蘇生 | 単体/全体 | 持久戦・立て直し |
| 防御 | ガード/かばう | 自己/味方 | 被ダメ軽減・的を引き受ける |
| 特殊 | 状態異常付与/封印/挑発/スカウト補助 | 各種 | 戦況コントロール |
| スカウト | スカウトアタック | 敵単体 | 仲間化（6章） |

### 5-6. ターゲット指定ルール

- 敵タップで**ロックオン**。そのコドモナの以後の行動は原則ロック対象へ。
- **未指定（空タップ/未操作）**：AIが「最もHP%が低い」または「弱点を突ける」敵を自動選択。
- **全体技**は対象指定不要（盤面で全体技が出たら全敵へ）。
- **対象が倒れたら**：ロックは自動で次の敵へスライド（手間ゼロ）。
- ロックは**ラウンドをまたいで継続**（連打不要＝片手快適）。

### 5-7. 全体 / 単体 / ランダム攻撃

- **単体**：高倍率。ターゲット指定が活きる。
- **全体**：低めの倍率を全敵に。複数残敵の処理に有効だが、スカウト前に倒しすぎる諸刃。
- **ランダム複数**：低倍率を2〜4回ランダムに。火力期待値は高いが制御不能（運要素）。
- → **「スカウトしたい敵を残しつつ削る」**判断が、技選択（盤面構成）と絡む戦略になる。

### 5-8. 状態異常（初期セット）

| 状態異常 | 効果 | 解除 |
| --- | --- | --- |
| 毒（むしばみ） | 毎手番に最大HP割合ダメージ | 数ターン/回復行動 |
| 麻痺（しびれ） | 一定確率で行動不可 | 数ターン |
| 眠り（ねむけ） | 行動不可。被弾で確率起床 | 被弾/数ターン |
| 混乱（めまい） | ターゲットがランダム化 | 数ターン/被弾 |
| 封印（ふうじ） | 必殺/特定枠が出なくなる | 数ターン |
| 鈍足/加速 | 素早さ減/増 | 数ターン |
| 攻↑↓ 守↑↓ | バフ・デバフ | 数ターン |

> **スカウトとの連動**：「眠り」「麻痺」中の敵はスカウト成功率に補正（隙を作る＝戦略）。

### 5-9. 属性相性

- 属性：**火 / 水 / 風 / 地 / 光 / 闇 / 無**（7属性）。
- 相性環：火→風→地→水→火（弱点ループ）、光⇔闇（相互弱点）、無は等倍（万能だが特効なし）。
- 倍率：弱点 ×1.5 / 等倍 ×1.0 / 耐性 ×0.66 / 無効化スキル持ちは ×0。
- 弱点ヒットで**画面演出＋ダメージ強調**（"刺さった"快感）。
- 解析（一度戦う/スキル）で弱点アイコンが図鑑＆戦闘UIに表示。

### 5-10. ランダム要素（会心・ミス・暴走）

- **会心（クリティカル）**：基本5〜10%、ステ/スキルで上昇。ダメージ×1.5〜2。専用SE＆フラッシュ。
- **ミス（外し）**：命中−回避で算出。基本ミス率は低め（理不尽回避）。鈍足/混乱で上昇。
- **暴走**：低確率で技が強化発動（ダメージ×2〜3 or 効果範囲拡大）。**ハイリスクハイリターン枠の華**。性格「やんちゃ」等で暴走率上昇。
- これらは**腕でコントロール可能**（会心UPバフ、命中バフ、暴走特化編成）にして「運ゲー」化を防ぐ。

### 5-11. ボス戦の特別ルール

- **複数HPバー（段階）**：一定割合でフェーズ移行、行動パターン変化。
- **専用ギミック例**：
  - 「とりまき召喚」：手下を呼ぶ（全体技や封印の重要度UP）。
  - 「属性シフト」：弱点属性が定期変化（柔軟な編成・複属性パーティが有利）。
  - 「怒りモード」：HP低下で行動回数増（速攻 or 耐久の択）。
  - 「ガードブレイク」：特定行動でガードを剥がしてから大ダメージ、の手順要求。
- **ボスはスカウト不可（原則）**。ただし章クリア後の「再戦・共鳴イベント」で限定スカウト枠を用意（長期目標）。
- ボス戦はテンポより**手応え**優先。1戦5〜8分許容。

### 5-12. オートバトル方針

- **オート（AI委任）**：ルーレットおまかせ＋AIターゲットで自動進行。周回・低年齢向け。
- **セミオート**：オートだがスカウト/必殺だけは手動点灯（取りこぼし防止）。
- **速度切替**：×1 / ×2。×2は演出短縮（数値ポップとSEは残す＝気持ちよさ維持）。
- オートでも**ロック中ターゲットは尊重**（途中介入で方針上書き可）。

### 5-13. 戦闘演出のテンポ設計

- 1手番の標準尺：**ルーレット0.6s → 移動/予備0.2s → 命中演出0.4s → ダメージ0.3s ≒ 1.5s**。
- ×2時：合計 ≒ 0.8s。
- ログは右に流す簡潔表記＋アイコン。読まなくても色とSEで分かる。
- 連戦周回時は「演出最小モード」（数値とSEのみ）を設定で選択可。

### 5-14. 縦式リールの気持ちよさ（演出案）

- 縦スクロールは**加速→減速のイージング**＋停止直前の"あと一枚"のタメ（パネルが停止ライン手前でぐっと遅くなる）。
- 停止時、停止ラインのパネルが**ポンッと拡大＋ハプティック「カチッ」**。★ランクの数だけ星が弾ける。
- 強★パネル（必殺/★★★★）停止時は**専用キラリSE＋発光＋停止ラインが金色化**。
- **ミス枠**で止まると軽い「スカッ」音＋脱力モーション（コミカルに。理不尽感を出さない）。
- ストップモード成功（強★パネルをジャスト停止）で「ナイス！」表示＋小ボーナス（次手番の会心率微増）＝腕報酬。
- 連続で強★を引くと**コンボ表示**（テンション演出。性能影響は少なめでOK）。
- レベルアップでパネルが化けた直後の戦闘は、そのパネルに**「NEW」バッジ**＝育った実感を即フィードバック。

## 6. スカウトシステム

「倒す」より「共鳴して仲間にする」を世界観・快感の核に。**低確率を粘るゲームにしない**。

### 6-1. 発動条件

- 各味方は手番のルーレットに**スカウト枠**を組み込める（育成で付与）か、**共通スカウトゲージ**満タンで `スカウト` ボタンが点灯。
- MVPでは扱いやすい **「共通スカウトゲージ方式」** を採用：
  - 攻撃/被弾/弱点ヒット/状態異常付与でゲージが貯まる。
  - 満タンで `スカウト` 点灯 → 対象敵を選んで実行。

### 6-2. 成功率の計算要素

`scoutChance = base × hpFactor × statusFactor × rarityFactor × charmFactor × partyFactor + gaugeBonus`

| 要素 | 内容 |
| --- | --- |
| base | 系統・ランクごとの基礎成功率（例 普通=35%、レア=12%） |
| hpFactor | 敵の残HP%が低いほど上昇（後述6-3） |
| statusFactor | 眠り/麻痺/混乱中で ×1.3〜1.6 |
| rarityFactor | レア・上位ランクは低め |
| charmFactor | 敵の性格/種族の「なつきやすさ」係数 |
| partyFactor | スカウト特化スキル持ち/同系統が編成にいると上昇 |
| gaugeBonus | **失敗するたび蓄積する"絆ポイント"を加算**（粘りが無駄にならない） |

- 上限/下限をクランプ（最低5%・最高95%）。確定でも理不尽失敗でもない設計。

### 6-3. 残HPと成功率の関係

- HP100%→補正なし、HP50%→＋中、HP20%以下→＋大。
- ただし**削りすぎ（撃破）= スカウト不可**。「弱らせるが倒さない」ライン管理が戦略の山場。
- UIで「あと少しで倒れる」敵には警告色＋"とどめ注意"表示。

### 6-4. 性格・種族による違い

- 性格に「なつきやすさ」係数（例：おっとり=高、きまぐれ=低、こうけつ=とても低）。
- 種族（系統）でも傾向：獣系/精霊系はなつきやすい、悪魔系/竜系は手強い。
- 図鑑にスカウト難易度（☆1〜5）を表示。

### 6-5. レアモンスターのスカウト条件

- レア個体は base が低い＋特定条件で出現（特定章/特定天候/低確率エンカウント）。
- **条件付き緩和**：状態異常2種重ねがけ、特定スカウト特化コドモナを編成、などで現実的確率に。
- 「運だけで取れない、準備すれば取れる」設計。

### 6-6. ボスモンスターの扱い

- 原則スカウト不可（5-11）。
- 章クリア後の**共鳴クエスト**で、条件達成時のみスカウト可能な特別個体を用意（長期目標・図鑑の華）。

### 6-7. 失敗時のリスク（軽め）

- 失敗＝**スカウトゲージ消費＋小リスク**（例：対象が怒り状態化＝攻撃力一時UP、または1ターン無防備にならない程度）。
- **ペナルティは軽微**に。低年齢がトラウマにならない範囲。
- 失敗しても**絆ポイント蓄積（6-2 gaugeBonus）**で次回成功率が上がる＝前進感を必ず残す。

### 6-8. 成功時の演出

- 対象が動きを止め、ハートor星の共鳴エフェクト → 光に包まれ → 味方枠へ「ぴょん」と着地。
- 「なかまになった！」＋図鑑更新＋専用SE。レアは画面全体演出。

### 6-9. スカウトを戦略的にする仕組み

- 「全体技で雑魚処理 vs 単体で削ってスカウト」のジレンマ。
- 状態異常→スカウトのコンボ設計。
- スカウト特化編成（成功率バフ/ゲージ加速）の構築余地。
- 「この敵を残しつつ、他を倒す」ターゲット管理。

### 6-10. ストレスにならない調整

- 最低成功率5%保証＋絆ポイント蓄積で**何度か挑めば必ず取れる**収束設計。
- 「もっと弱らせると上がるよ」「眠らせると上がるよ」の能動ヒント。
- レアは渋くても、通常モンスターはサクサク仲間化（図鑑が気持ちよく埋まる）。

## 7. 配合システム

完全固定だけにしない**汎用配合（系統×ランク×相性で決定）**を基盤に、**特殊配合（限定レシピ）**を重ねる。
詳細レシピは [`data/fusion_rules.json`](../data/fusion_rules.json)。

### 7-1. モンスターの系統分類（10系統・オリジナル）

| 系統 | キーカラー | イメージ |
| --- | --- | --- |
| 獣系（ケモノ） | オレンジ | 四足・牙・俊敏 |
| 竜系（ドラグ） | 赤 | 翼・鱗・威厳 |
| 魔法系（マギ） | 紫 | 杖・ローブ・知性 |
| 植物系（フロウ） | 黄緑 | 蔓・花・再生 |
| 物質系（マテル） | 灰 | 鉱物・粘体・無機 |
| 水棲系（アクオ） | 青 | 鰭・流線・水流 |
| 鳥系（プルム） | 水色 | 羽・嘴・飛翔 |
| 悪魔系（デモル） | 黒赤 | 角・影・トリッキー |
| 精霊系（スピリ） | 白金 | 光・浮遊・補助 |
| 機械系（メカニ） | シアン | 装甲・回路・人工 |

### 7-2. ランク分類

`G < F < E < D < C < B < A < S < SS`（9段階）。
- 章進行と配合でしか到達できない上位ランク（SS は終盤＋特殊配合）。
- ランクは**ステータス上限・習得スキル枠数・ルーレット枠数**に影響。

### 7-3. 汎用配合ルール（基盤）

1. 親A・親Bの**系統と相性表**から子の系統を決定。
   - 同系統同士 → 同系統の上位寄り。
   - 異系統 → 相性表に基づく「掛け合わせ系統」（例：獣×竜=竜寄りの獣＝"竜獣"枠）。
2. 子の**ランク** = `floor((親A rank + 親B rank)/2) + ボーナス`。
   - ボーナス：両親が同種/高相性/高Lvだと＋1段階。
3. 子の**具体種** = 決定系統×ランク帯の候補プールから、引き継ぎ要素と乱数で抽選。
4. 候補が複数ある場合は**配合プレビューで候補名を提示**（完全固定でないが予測可能）。

### 7-4. 特殊配合ルール（限定レシピ）

- 特定の親組み合わせ（種指定 or 系統×条件指定）でのみ生まれる固定結果。
- 例：「炎竜 × 氷霊（特定2体）→ 双極竜（SS素材）」。
- 条件に「親が特定スキル習得済み」「親Lv上限」「特定章クリア後」などを付与可能（やり込み）。
- 図鑑で**一部だけヒント開示**（全部は見せず、発見の喜びを残す）。

### 7-5. 配合結果の決まり方（優先順位）

1. **特殊配合レシピに合致** → そのまま固定結果。
2. 合致しない → **汎用ルール**（7-3）で系統・ランク・候補プール決定 → 抽選。
3. 引き継ぎ要素（スキル/属性/性格）は別途継承処理（7-6〜7-10）。

### 7-6. 親から子へ引き継ぐ要素（概要）

| 要素 | 引き継ぎ | 備考 |
| --- | --- | --- |
| スキル | 親の習得スキルから**最大2つ選んで継承**（プレイヤー選択） | 7-7 |
| ステータス | 親平均の一部を**初期値ボーナス**として加算 | 7-8 |
| 属性 | 親属性のいずれか/混合 | 7-9 |
| 性格・個性 | 確率で親から継承 or 新規抽選 | 7-10 |
| 系統・ランク | ルールで決定（直接は継承でなく算出） | 7-3 |

### 7-7. スキル継承

- 親A・親Bの習得スキルリストから**プレイヤーが最大2つ選択**して子に継承。
- 系統不一致のスキルは継承時にコスト増 or 一部不可（無双化防止）。
- これにより「素材で技を運ぶ」配合戦略（DQM的奥深さのオリジナル版）が成立。
- 継承スキルは子のルーレット枠に**初期セット**される。

### 7-8. ステータス継承

- 子の初期ステ = 種の基礎値 ＋ `親平均ステ × 継承係数（例0.15）`。
- 高ステ親で配合を重ねると**世代を経るほど強くなる**（やり込みの軸）。
- 上限はランクでクランプ（インフレ抑制）。

### 7-9. 属性継承

- 子の属性 = 種固有属性を基本に、親属性で**サブ属性付与**の可能性。
- 例：火の種＋水親 → 火（主）＋水耐性（副）。複属性化で相性戦略が深まる。

### 7-10. 性格・個性の継承

- 性格（やんちゃ/おっとり/こうけつ/きまぐれ/まじめ 等）は確率継承 or 新規。
- 性格はステ補正・暴走率・なつきやすさ・成長傾向に影響。
- 「個性」（小特性。例：会心+5%、毒耐性）も低確率で継承。

### 7-11. 配合で失われるもの / 残るもの

- **失われる**：親2体は消費（消滅）。親のLv・余剰スキル（継承で選ばなかったもの）。
- **残る**：選んだ継承スキル、ステ継承ボーナス、属性・性格の一部、そして**図鑑記録（親は図鑑に残る）**。
- 「消えるけど記録と力は子に受け継がれる」＝情緒的にも納得できる設計。

### 7-12. 後悔しにくいUI設計

- 配合前に**必ず確認モーダル**（「親2体は旅立ちます」）。
- **ロック機能**（お気に入りは誤配合不可）。
- **直前1回のアンドゥ猶予**は技術的に難しいので、代わりに**確認＋プレビュー＋ロック**の三重防御。
- 重要素材には「素材になっても図鑑に残ります」と明記。

### 7-13. 配合結果を事前にどこまで見せるか

- **見せる**：子の系統、ランク帯、候補種名（複数なら複数）、継承予定スキル、属性、新規/特殊配合バッジ。
- **見せない（楽しみに残す）**：最終的にどの候補が出るか（抽選）、ステの正確な乱数、まれな個性発現。
- → 「設計はできるが、毎回少しの驚きがある」黄金比。

### 7-14. 配合検索・逆引き機能

- **逆引き**：図鑑/目的のコドモナから「これを作るには？」を検索 → 必要な親系統/レシピを提示（特殊配合は一部のみ開示）。
- **正引き**：手持ち2体を仮選択して結果プレビュー。
- 所持素材でたどり着けるレシピを**ハイライト**。

### 7-15. 初心者向けおすすめ配合

- 「おすすめ配合」ボタン：手持ちから**図鑑が増える/戦力が上がる**配合を自動提案。
- 「次の章に向けてこの配合がおすすめ」とゲーム進行に紐づけた提案。

### 7-16. やり込み勢向け高難度配合

- 多段配合（4世代/8世代を遡る系図）で到達する SS 種。
- 「全継承スキル最適化」「特定個性の固定化（同個性親を重ねる）」の最適化パズル。
- 隠し特殊配合（条件難）＝図鑑コンプの最後のピース。

## 10. 育成システム

### 10-1. レベルアップ / 経験値

- 戦闘勝利・スカウトで経験値。レベルでステ成長。
- Lv上限はランクに依存（例 F=20、D=40、A=70、SS=99）。配合で上限を引き上げる動機。

### 10-2. ステータス

- `HP / 攻撃 / 防御 / 魔力 / 素早さ / 命中 / 運（会心・スカウト寄与）`。
- 成長率は系統・性格で傾向（獣=攻速、物質=HP防、精霊=魔回復 等）。

### 10-3. レベルアップによる「パネル・ランダム成長」（オレカ式・育成の核①）

本作の育成の最大の特徴。**レベルアップごとに、リールの1枚（パネル）がランダムで別の技／上位の技に変化する**。

- レベルが上がるたび、**ロックしていないパネルの中から1枚**が抽選で変化。
  - 変化の例：`ミス → ★ひっかき` / `★ひっかき → ★★かみつき` / `★★うなり → ★★★みだれ爪` など。
- 変化先は、その個体の**系統（family）プールと属性**から抽選（獣系なら獣系技、火属性なら火技が出やすい）。
- まれに**飛び級変化**（★→★★★）や**必殺パネル（★★★★）出現**が起き、当たり個体になる＝**一喜一憂と厳選の深さ**。
- これにより、**同じ種でもリール構成が個体ごとに違う**＝「自分が育てた唯一の子」という所有感（独自要素①）。

> オレカバトル式の"育成の引き"。決定論ではないが、後述のロックとリロールで**理不尽な事故は抑える**。

### 10-4. 技の強化・固定（オレカ式・育成の核②）

- **パネルロック**：気に入ったパネルは**ロック**して以後の変化対象から除外（育てた技を守る）。
- **リロール素材**：満足いかない変化を**振り直す**素材を用意（事故救済・厳選の主導権をプレイヤーに）。
- **技強化**：各技にランク（Lv1〜5）。素材で強化＝威力/効果/命中UP（パネルの★が育つ）。
- 「どのパネルをロックし、どれを変化に賭けるか」が腕の見せどころ。

### 10-5. リールの「型（フレーム）」をプレイヤーが構成する（育成の核③）

中身（技）はランダム成長だが、**器＝型（フレーム）はプレイヤーが設計**できる。これが「運任せ」と「自己設計」の両立点。

- **パネル数**：初期4 → 育成/ランクで最大8（枠を増やすほど選択肢と事故率が両立）。
- **型テンプレート**：攻撃寄り／補助寄り／必殺特化 など**変化の傾向（プール重み）を方針として指定**できる。
- **ロック構成**：どの枠を固定し、どの枠を変化に開けておくか＝**安定型／博打型／補助型**の個性が出る。
- これが本作の育成の差別化点＝**編成＝メンバー、育成＝リールの型づくり＋成長の引き**。

### 10-6. 進化 / 覚醒

- **覚醒**（6章解放）：特定Lv＋素材で見た目・ステ・枠数が一段上昇（"可愛い→かっこいい"の見た目変化を報酬化）。
- 進化は配合と役割分担：**覚醒＝同一個体の強化、配合＝新個体の創造**。

### 10-7. 装備・アクセサリ

- **MVPでは入れない**（複雑化回避）。Phase2で「共鳴石（アクセサリ枠1）」を検討。
- 入れる場合も1枠・効果は控えめ（編成と育成の主役を食わない）。

### 10-8. 性格・個体差

- 性格はあり（7-10）。個体差（同種でも微ステ差・個性有無）も導入。
- ただし**過度な厳選を強制しない**：性格変更アイテムを用意し、ライト層がストレスを感じない逃げ道を作る。

### 10-9. 初心者が迷わない育成導線

- 「おすすめ育成」ワンタップ（Lv上げ→推奨型テンプレ→推奨ロック構成を自動適用）。
- 重要操作のみ手動、細部は任意。

### 10-10. やり込み勢が長く遊べる要素

- リールの厳選（理想パネル構成の引き＋ロック＋リロール最適化）、覚醒＋多段配合の最強個体、個性固定、全系統の最高ランク収集、図鑑コンプ。

## 11. アート・UI方針

### 11-1. モンスターデザイン原則

- 低ランク：丸・大きな目・短手足（可愛い）。高ランク/覚醒：エッジ・装甲・流線（かっこいい）。
- 系統ごとにシルエットとキーカラーを固定（7-1表）。一目で系統が分かる。
- 表情差分（通常/戦闘/勝利/被弾/なつき）で生命感。

### 11-2. UIパーツ方針

- **角丸カード**を基本単位（モンスター/ステージ/報酬すべてカード化）。
- **ルーレット**は**縦式リール**（円形回転ではない）。停止ラインを中央に、パネルは行動アイコン＋★ランク＋系統色。スロットマシンの1リールの見た目。
- **属性アイコン**は7色＋形（色覚配慮で形でも区別）。
- フラット＋微シャドウ。情報階層は余白とサイズで表現。

### 11-3. 色使い

- ベースは明るいクリーム/空色（やさしさ）。
- アクセントに系統キーカラー。
- 戦闘は背景を少し落ち着かせ、エフェクトの色を映えさせる（かっこよさ）。

### 11-4. フォント

- 日本語：丸ゴシック系（可愛い・可読）。見出しは太丸ゴシック。
- 数字/英字：やや幾何学的サンセリフ（本格感）。
- ふりがなトグル（低年齢配慮）。

### 11-5. ボタンデザイン

- 主要：塗りつぶし＋立体感（押せると分かる）。
- 副次：アウトライン。
- 確定系は大きく右下、戻る系は左下。アイコン併記。

### 11-6. バトルエフェクト

- 属性ごとに色とパーティクル。弱点ヒットは大きめフラッシュ。
- 会心は集中線＋拡大。被弾はカメラ微振動。
- 低スペック向けに**エフェクト品質3段階**（高/中/低）を設定で切替。

### 11-7. スカウト成功演出

- 共鳴リング → 光に包む → 味方枠へ着地 →「なかまになった！」。
- レアは画面全体の星エフェクト＋専用ジングル。

### 11-8. 配合演出

- 親2体が光の繭で混ざる → 繭がふくらむ → 割れて子が登場。
- 特殊配合/高ランクは繭の色・割れ方・SEを格上げ。

### 11-9. レア出現演出

- エンカウント時に背景が金色化＋専用SE（"何か違う"の予感）。
- 図鑑/配合のレア結果はカード枠がプリズム発光。

### 11-10. 低スペック方針

- すべての派手演出に**簡易フォールバック**。FPS低下検知で自動降格。
- スプライトシート＋CSS/Canvasで軽量。動画は使わない。

### 11-11. PWA向け画面構造

- 単一ページアプリ（SPA）＋ルーティング。画面はコンポーネント遅延ロード。
- 共通：上部ステータスバー / 中央コンテンツ / 下部アクション帯の3層。

## 12. PWA開発仕様

### 12-1. スマホ縦画面最適化

- 基準 390×844、セーフエリア（ノッチ/ホームバー）考慮。
- レイアウトは `svh/dvh` 単位＋Flex/Grid。横画面は非対応 or 「縦にしてね」案内。

### 12-2. オフライン対応の範囲

- **オフラインで動く**：ホーム、編成、育成、配合、図鑑、**シングル戦闘（ローカル完結）**。
- **オンライン推奨**：クラウドセーブ、お知らせ、（将来）イベント/対戦。
- Service Worker でアプリシェル＋静的データ（monsters/fusion/chapters JSON）をキャッシュ。

### 12-3. データ保存方法

- 進行データ：**IndexedDB**（大きめ・構造化。所持モンスター・図鑑・進行）。
- 設定/軽量フラグ：`localStorage`。
- セーブはオートセーブ（重要操作後＋一定間隔）。

### 12-4. ローカル vs サーバー保存の切り分け

| データ | ローカル(IndexedDB) | サーバー(将来) |
| --- | --- | --- |
| 所持モンスター/育成 | ◎ 主 | ○ バックアップ/同期 |
| 図鑑/進行 | ◎ 主 | ○ 同期 |
| 設定 | ◎ | × |
| アカウント/課金/イベント | × | ◎ |

- MVPは**完全ローカル**。Phase2でアカウント連携（引き継ぎコード→クラウド）。

### 12-5. 初期バージョンで必要な機能 / 後回しでよい機能

- **必要（MVP）**：1章、12体、4v4ルーレット戦闘、スカウト、簡易配合、図鑑、編成、育成（Lv/盤面）、ローカルセーブ、PWAインストール。
- **後回し**：覚醒、特殊配合の大量レシピ、装備、クラウドセーブ、イベント、対戦、サウンドのフル実装、多言語。

### 12-6. 画面遷移の構造

```
/title
/home
  /chapters → /stages → /battle → /result → /reward
  /party
  /monsters → /monster/:id → /train/:id
  /fusion → /fusion/result
  /dex → /dex/:id
  /settings
```

- ルーターは履歴管理＋戻るジェスチャ対応。戦闘中は離脱確認。

### 12-7. コンポーネント設計（推奨スタック）

- **推奨**：TypeScript ＋ React（or Vue）＋ Vite ＋ PWA Plugin ＋ Zustand/Pinia（状態）。
- 共通UI：`Card` / `RouletteWheel` / `MonsterSprite` / `StatBar` / `AttributeIcon` / `BottomSheet` / `ActionBar`。
- 画面＝ページコンポーネント、機能＝フィーチャーフォルダ（feature-based構成）。

### 12-8. バトル処理の設計（最重要・分離が肝）

- **純粋なバトルエンジン（UI非依存）**：
  - `BattleState`（ユニット配列・ターンキュー・乱数シード）。
  - `step(state, action) -> { nextState, events[] }`（イベント駆動）。
  - 乱数は**シード付き**（再現・テスト・将来のリプレイ/同期に有利）。
- **ビュー層**：`events[]` を受け取りアニメ再生。結果とは独立（演出スキップ/×2が容易）。
- これにより**ロジックはユニットテスト可能**、演出は差し替え自由。

### 12-9. モンスターデータ管理

- マスタは静的 `data/monsters.json`（種データ＝種族値・初期盤面・系統・属性）。
- 所持個体は IndexedDB（種ID参照＋個体差・Lv・盤面・性格・継承スキル）。
- 種データ＝不変、個体データ＝可変、を明確に分離。

### 12-10. 配合データ管理

- `data/fusion_rules.json`：相性表（系統×系統→子系統）、ランク計算、特殊配合レシピ配列、継承ルール。
- 配合は純関数 `previewFusion(parentA, parentB)` / `executeFusion(...)`。テスト容易。

### 12-11. 将来のネイティブ化への注意点

- **Capacitor**（or React Native ＋ロジック移植）でラップ前提。
- DOM依存を抑え、ロジックは純TS（プラットフォーム非依存）に隔離。
- ストレージ抽象化（`StorageAdapter`：Web=IndexedDB、Native=SQLite/AsyncStorage）。
- 入力はタップ中心（ネイティブでもそのまま通用）。重い演出はWebGL/Canvasで移植容易に。
- 課金/プッシュは抽象インターフェース化し、Web版ではスタブ。

## 13. MVP設計

### 13-1. MVPゴール

「**1章を最後まで遊べて、4v4ルーレット戦闘・スカウト・簡易配合・図鑑が一通り回る PWA**」を、個人〜少人数で完成させる。

### 13-2. MVPに含める機能

- タイトル/ホーム/章選択(1章のみ)/ステージ選択/編成/モンスター一覧・詳細/育成(Lv＋盤面)/簡易配合/配合結果/図鑑/設定。
- 4v4ルーレットバトル（おまかせ＋手動ストップ、ターゲット指定、属性7種、状態異常3〜4種、会心/ミス）。
- スカウト（共通ゲージ方式、絆ポイント蓄積）。
- 簡易配合（汎用ルール＋特殊配合2〜3レシピのみ）。
- モンスター **12体**（[`monsters.json`](../data/monsters.json) の #01〜#12 を中心に、各系統入門＋数体）。
- ローカルセーブ（IndexedDB）、PWAインストール、オフライン戦闘。

### 13-3. MVPに含めない機能（明確に切る）

- 覚醒、装備、クラウドセーブ、対戦、イベント、2章以降、特殊配合の大量レシピ、フルサウンド、多言語、性格変更アイテム（性格は固定抽選のみ）。

### 13-4. 開発順序（推奨スプリント）

1. **S1 — 基盤**：プロジェクト雛形(Vite+TS+React+PWA)、ルーティング、データJSONローダ、ストレージ抽象。
2. **S2 — バトルエンジン（UIなし）**：`BattleState`/`step`/乱数シード/属性/状態異常/会心。ユニットテスト先行。
3. **S3 — バトルUI**：敵味方表示、ルーレット盤、ターゲット指定、イベント駆動演出、速度切替。
4. **S4 — スカウト**：ゲージ・成功率関数・成功/失敗演出・仲間化フロー。
5. **S5 — 育成**：Lv/経験値/盤面カスタム/スキル装着。
6. **S6 — 配合**：プレビュー/実行/継承選択/結果画面/簡易特殊配合。
7. **S7 — メタ画面**：ホーム/章・ステージ選択/編成/図鑑/設定。
8. **S8 — 1章コンテンツ実装**：ステージ・敵配置・ボス・報酬・チュートリアル。
9. **S9 — 仕上げ**：PWA最適化、低スペック演出降格、セーブ堅牢化、バランス調整。

> ポイント：**S2のバトルエンジンを先に純ロジックで完成・テスト**してからUIを乗せる。手戻りが激減する。

### 13-5. テスト方法

- **ユニットテスト**：バトルエンジン（ダメージ式/属性/状態異常/行動順）、配合の純関数（プレビュー/継承）、スカウト成功率関数。Vitest 推奨。
- **シナリオテスト**：シード固定で「同じ入力→同じ結果」を検証（リグレッション）。
- **手動UXテスト**：実機（中〜低スペック Android/iPhone）で片手操作・テンポ・可読性を確認。
- **子どもユーザビリティ確認**：実際に低年齢層に触ってもらい「どこで詰まるか」を観察。
- **バランス計測**：1章クリア所要時間、平均戦闘時間（2〜5分目標）、スカウト成功までの平均試行数を計測しチューニング。

### 13-6. MVP完成の定義（DoD）

- 新規プレイヤーがチュートリアル込みで**1章をクリア**できる。
- 4v4戦闘が**2〜5分**で、片手で完結する。
- スカウト・配合・育成・図鑑が一通り体験でき、図鑑が**12体中8体以上**自然に埋まる。
- オフラインで起動・戦闘でき、再起動でセーブが復元される。
- 中スペック端末で戦闘が**30fps以上**を維持（低演出モードで低スペックも可）。

## 14. 今後決めるべき論点

1. **マネタイズ方針**：低年齢配慮と収益の両立（買い切り/広告/控えめなガチャ無しの素材販売 等）。倫理ラインを最初に決める。
2. **スタミナ/周回設計**：気軽さを損なわない範囲でのプレイ制限の有無。
3. **ルーレット手動介入の比重**：おまかせ既定だが、手動ストップをどこまで"勝ち筋"にするか（運と腕の最終比率）。
4. **配合の見せる/隠すの最終調整**：プレビュー開示度（後悔回避 vs 発見の喜び）。
5. **性格・個体差の厳選圧**：ライト層が萎えない範囲の設計（変更アイテムの入手難度）。
6. **モンスター総数のロードマップ**：30体→最終何体か、系統バランスとアート工数。
7. **オンライン要素の射程**：対戦/協力/イベントを将来入れるか（バトルエンジンのシード設計に影響）。
8. **アート制作体制**：30体×表情差分＋覚醒形のコスト。内製/外注/生成補助の方針。
9. **サウンド方針**：BGM/SEの調達と容量（PWAの軽量性とのトレードオフ）。
10. **アクセシビリティ**：色覚・難語・操作支援（ふりがな/読み上げ）の対応範囲。
